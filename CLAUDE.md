# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SaiyanTrainer is an Expo (SDK 57, React Native 0.86, React 19.2, New Architecture only, Hermes V1) Android app for logging gym training and meals, with a Dragon Ball theme. The UI text and code comments are in Croatian; keep new comments and user-facing strings in Croatian. Plain JavaScript (`.js`/`.jsx`), no TypeScript and no tests.

## Commands

- `npx expo start --go`: dev server for Expo Go (the user tests on their phone in Expo Go for SDK 57). Without `--go` the CLI targets a dev client, because `expo-dev-client` is installed.
- `npx expo install <pkg>` / `npx expo install --fix`: add or align packages to SDK 57 versions. Check with `npx expo-doctor@latest`. Its "non-CNG project" warning is expected, because `android/` is committed.
- `npx expo export --platform android --output-dir dist`: checks that the whole app bundles. The user prefers to test in Expo Go instead, so don't run it after every change. `dist/` is gitignored; delete it afterwards.
- `npx expo lint` / `npx eslint`: currently broken. ESLint 9 is installed but the config is the legacy `.eslintrc.json`, so there is no working linter.
- Release APK (local, no EAS): the native C++ build fails from this deep project path (Windows 260-char limit in ninja; `subst` does not help because Node/Gradle resolve the real path). Build from a short-path clone instead: `git clone <this repo> C:\st`, copy `.env` there, `npm ci`, then in `C:\st\android` run `gradlew.bat assembleRelease "-PreactNativeArchitectures=arm64-v8a,x86_64"` (quote it in PowerShell). For later builds, `git pull` in `C:\st` and rebuild. Set `JAVA_HOME` to Android Studio's JBR (`C:\Program Files\Android\Android Studio\jbr`, JDK 21), because the system Java is 24 and too new. Also set `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk` (there is no `android/local.properties`). Output: `C:\st\android\app\build\outputs\apk\release\app-release.apk`, signed with the debug keystore.
- EAS profiles exist in `eas.json` (`development` = dev client, `preview`/`production` = standalone APK). `.env` is gitignored, so EAS cloud builds need the `EXPO_PUBLIC_*` vars defined as EAS env vars.

The native `android/` folder is committed and was generated by `npx expo prebuild --platform android` (SDK 57 prebuild clears and regenerates the folder). Changes to `app.json` native config (icon, name, plugins) only apply after prebuild runs again. Launcher icons are generated from `assets/images/vegeta_icon.png` and `adaptive-icon.png`. Don't hand-edit `android/`; regenerate it instead.

**Dependencies:** `package.json` has `overrides` so that `react-native-appwrite` uses the project's `expo-file-system` (Appwrite pins v18 from SDK 53). Since SDK 56, `expo-router` vendors React Navigation, so don't add `@react-navigation/*` packages; import navigation APIs from `expo-router`. `react-native-reanimated`, `react-native-worklets` and `react-native-gesture-handler` are only there because expo-router's drawer layout requires them. Since SDK 56, global `fetch` is `expo/fetch`. If Appwrite requests misbehave, `EXPO_PUBLIC_USE_RN_FETCH=1` in `.env` restores the RN fetch.

## Environment

`.env` provides `EXPO_PUBLIC_APPWRITE_*` (endpoint, project, DB and collection IDs, package/bundle name). These are inlined into the JS bundle at build time. `EXPO_PUBLIC_APPWRITE_PACKAGE_NAME` is what Appwrite validates as the Android "App" (sent as the `Origin: appwrite-android://<value>` header). It is not the real Android package `com.marinko369.SaiyanTrainer`.

## Architecture

**Routing** (expo-router, `app/`): root `_layout.jsx` is a Stack wrapped in `AuthProvider`. `index.jsx` redirects to `auth/` or `(screens)/trainingScreen`. `(screens)/_layout.jsx` wraps `components/TabLayout.jsx` in `DateProvider`. `TabLayout` defines the bottom tabs, the header actions (avatar button → profile, logout), and the floating calendar button and modal. `profileScreen` is a tab hidden from the tab bar (`href: null`). Each screen redirects to `/auth` itself when there is no user.

**Auth and username:** the username ("Saiyan name", lowercase, 3–20 chars of `[a-z0-9_.]`) is the Appwrite user's `name`. Appwrite only supports email sessions, so `AuthContext.login` accepts an email or a username. For a username, it first calls the Appwrite Function `appwrite/functions/username-lookup` through `services/usernameService.js`. The function ID comes from `EXPO_PUBLIC_APPWRITE_FN_USERNAME_ID`. The function has execute access "Any" and the `users.read` scope. Its actions are `check` (username available?) and `lookup` (email for a username). The function is deployed manually in the Appwrite console; setup steps are in `USERNAME.txt`.

**Data storage is split across three places:**
- **Appwrite** (`services/appwrite.js` → `databaseService.js` → `saiyanService.js`) holds the `exercises` and `meals` collections. Documents are filtered by a `user_id` field and paged 100 at a time (`listAllForUser`). Every service function returns `{ data, error }` instead of throwing. The meals collection stores integer `calories`/`protein` only, and `mealName` is the name field.
- **Appwrite account prefs** (`user.prefs`, via `AuthContext.savePrefs` → `account.updatePrefs`) hold `profile` (height, weight, age range, activity, goal…) and `avatar`. `updatePrefs` replaces the whole prefs object, so always merge with the existing `user.prefs`.
- **AsyncStorage** (device-local, per user) holds user-added custom exercises (`services/exerciseCatalog.js`) and custom foods (`services/foodCatalog.js`). These are merged with the bundled libraries `components/workout_exercises.json` and `components/foods.json` (values per 100 g).

**Dates** (`contexts/DateContext.js`, `utils/dates.js`): the context holds `selectedDate` plus `mode` (`'day' | 'week' | 'month' | 'all'`), and derives `range`, `rangeLabel` and `entryDate` (the date new entries are saved to). It resets to today on app foreground (AppState) and on every tab change (a `pathname` effect in `TabLayout`). Screens fetch all of a user's documents and filter client-side with `inRange`. In multi-day modes they insert `type: 'day'` header rows via `withDayHeaders`. Entry dates are stored as `new Date('YYYY-MM-DD').toISOString()` (UTC midnight) and compared with `dateKey()` (the UTC date part). Keep that convention.

**Nutrition** (`utils/nutrition.js`): pure functions for the profile. BMR uses Mifflin-St Jeor, or FAO/WHO for ages 13–18. TDEE is BMR × activity factor. The goal applies 7700 kcal/kg per month. Protein g/kg depends on activity level, plus 0.2 in a deficit. `calorieStatus`/`proteinStatus` drive the green/red goal text on the meals screen. They take a `days` multiplier: in week and month modes the period totals are compared with daily target × days.

**Training volume** (`utils/volume.js`): sets × reps × weight per exercise. Rep ranges are stored as their lower bound. `trainingScreen` shows the volume per exercise, per day (in day headers) and for the whole range (list footer).

**Muscles**: `utils/muscles.js` defines the 17 muscle keys stored on each exercise. The body figure (`BodyFigure.jsx`) is built from tinted PNG layers listed in `components/bodyLayers.js` (generated; `assets/body/`). Taps are mapped via `utils/bodyHitTest.js`. `utils/muscleStats.js` computes weekly per-muscle counts for `muscleScreen`.

## Conventions and gotchas

- **No native SVG.** `react-native-svg` was removed on purpose. Graphics are PNGs (body layers, `assets/images/avatars/*.png`, registered in `components/avatars.js`) or plain Views (`KettlebellSlider.jsx`).
- **Fabric integer props.** On Android Fabric, props typed as integers throw "Loss of precision during arithmetic conversion" if given a float (e.g. `accessibilityValue.now`). Round such values.
- **`KettlebellSlider` gestures.** It uses `PanResponder` with `collapsable={false}` and a `pointerEvents="none"` drawing layer. Position comes from `locationX/Y` at grant and `pageX/Y` while moving, so dragging outside the track works. The parent disables `ScrollView` scrolling during a drag through `onDragStart`/`onDragEnd`.
- Number inputs accept a decimal comma. Parse them with `utils/parseNumber.js`.
- Import alias `@/` maps to the project root (`babel.config.js`). `@env` (react-native-dotenv) is used only by the unused `api/huggingface.js`.
